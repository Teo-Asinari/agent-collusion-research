## Checks against actual source

**Colosseum.** Inspected `experiments/collusion/run.py`, `prompts.py`, metrics, collusion README and the A–D/positive-control YAMLs. The `simple` variant explicitly tells a pair to coordinate for coalition reward. The runner's `coalition_prompt: auto` couples instruction with secret-channel availability; `always`/`never` allow separating them. Added-channel membership can be coalition-only or everyone. A–D supply useful contrasts, but they are not a complete instruction × private-channel 2×2: the unprompted-channel arm is public, not private. Add a private/unprompted cell if that estimand matters. Ordinary topology messages and action effects persist when the *extra* channel is disabled.

The cheap positive-control config uses a single seed and shortened planning. A negative pilot sign does not establish absence of capability; a positive one does not establish reliable collusion. Identify treatment pairs in advance rather than selecting the best-performing subgroup after observing rewards. Preserve turn order and task costs in analysis.

**Voluntary-collusion games.** Inspected the main README, Liar's Bar offer prompt and relevant file structure. The offer states secret communication, advantage, unfairness and scarcity; this is an elicitation treatment. Defaults in the hosted adaptation substitute some original model checkpoints. `LLM_MODEL` can override every seat and monitoring role, so record effective IDs by role. Fallback actions after output errors can change behavior and must be counted. The recent paper appendix need not be implemented by the older bundled game code; do not assume source parity.

**Audit pipeline.** Inspected `colludebench/runner.py`, scripted/LLM agent modules, default config, feature extractor and MI/permutation detectors. The runner supplies payload bits to designated colluders; scripted channels are explicit. MI uses cross-run agent text features including length, digits and a watermark lexicon, not a generic action-influence causal estimator. It must be evaluated on held-out mechanisms and nulls.

**Specific correctness concern:** [`auditor/detectors/permutation.py`](https://github.com/poseidon-research/collusion_hackathon/blob/e6fb1308dae9cf97ae42aec1c5f7889d9e2291e8/steganographic-collusion/auditor/detectors/permutation.py) computes a mean distance from the centroid, then forms its null by shuffling the same list of vectors. That statistic is invariant to list order. An isolated standard-library check of the two arithmetic functions over all 24 permutations of four distinct vectors returned the identical score `4.182767761636298` (range 0). This is a mathematical defect in that null construction, not evidence that the entire detector stack fails. No upstream fix or full rerun was performed. See [feasibility-checks.md](feasibility-checks.md) for reproduction.

The audit README also warns about appended duplicate transcripts. We did not independently recount the raw corpus. Any data reuse must split/deduplicate first and keep whole episodes separated across calibration/evaluation.

**Pricing replacement.** Inspected `llm-cartel/branch_game.py`: agents are stateless API calls conditioned on visible history. “Fresh instance of the same model” with unchanged context is not a distinct replacement treatment. Change model, prompt, or retained history for a substantive contrast; cluster inference by base trajectory. `llm-agent-collusion/.../simulation.py` exposes seller communication, oversight sampling and pressure controls plus seed/metadata logging.
