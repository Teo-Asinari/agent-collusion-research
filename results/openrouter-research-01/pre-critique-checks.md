# Independent checks identified before reading cross-family critiques

These are primary-agent objections to initial model proposals, not additional hosted calls. Created during the batch before critique outputs were inspected. They will be checked against final revisions; none is a novelty claim.

1. **Gemini architecture: selective proof success.** If a fixed safe program is beyond the bounded fallback, a model can submit a valid invariant for bit 1 and an invalid invariant for bit 0. The published verification-success bit then equals the payload. Defining the authorized function using neural proof success is not a sender-independent task specification. Fixed timing does not fix this content channel.
2. **Sonnet architecture: first-match initialization.** The displayed min-record transition sets `found=1` and updates `min_rec` only when the matching record is below its initial zero. For a nonmatching first candidate and later positive-valued match, this literal rule can leave zero as the result. The proof prose assumes an initialization rule missing from the table. Even after repair, full min search leaves no demonstrated neural advantage; the suggested equality-predicate check makes every matching record identical and therefore misses meaningful tie selection.
3. **Gemini rewrite: unsupported global hardness.** Rejecting sender-restricted e-graph extraction is justified when sender traces induce different extraction sets. It does not establish that all useful sanitization needs global NP-witness canonicalization, that a common law must be a unique canonical form, or that useful verification/reconstruction can never save work. Its own packet contains restricted rerandomization/certification counterweights. No general reduction or impossibility theorem was supplied.
4. **Sonnet rewrite: fallback invalidates the incentive premise.** The existing sanitizer returns task-valid output on invalid submissions through independent fallback. Therefore task acceptance can be one while valid-certificate submission is zero. Rationality alone does not imply a fast-path distribution. A benchmark with exogenously valid certificates is legitimate but must not be inferred from acceptance. Failing one runtime threshold also does not establish strict dominance of re-solving or rule out all task families.

These checks test operational claims, not model intent. Model agreement cannot resolve them without a correct argument. No code from model outputs will be executed automatically.
