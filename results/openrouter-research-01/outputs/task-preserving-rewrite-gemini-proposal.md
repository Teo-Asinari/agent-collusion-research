Here is a concrete evaluation of the next logical step for the task-preserving-rewrite direction. Based on the constraints of information flow and computational complexity, I propose a specific construction, analyze it, and ultimately **reject** it, identifying the fundamental unresolved barrier to general task-preserving sanitization.

### Proposed Research Move: Trace-Restricted E-Graph Canonicalization

**Specific Useful Capability:**
Reusing expensive, search-heavy algebraic or tensor-graph optimizations (e.g., compiler rewrites) without leaking information through the sender’s specific choice of rewrite sequences or intermediate representations.

**Operational Construction:**
1. **Task:** Optimize an input expression $E$ given a public set of rewrite rules.
2. **Submission:** The sender provides a highly optimized expression $E_{opt}$ and a formal rewrite trace (a sequence of rule applications) proving $E \equiv E_{opt}$. Finding this trace is computationally expensive (analogous to equality saturation search).
3. **Verification:** The receiver deterministically checks the trace. If any step is invalid, it falls back to a safe, unoptimized default $E$. Verification is $O(L)$ where $L$ is trace length.
4. **Reconstruction (Sanitization):** The receiver constructs a restricted E-graph (equivalence graph) containing *only* the expressions and e-classes generated by the submitted trace. It then runs a strictly deterministic extraction algorithm (e.g., minimizing a public cost function, with strict lexicographic tie-breaking on the AST) over this restricted E-graph to produce the canonical output $E_{canon}$.

**Exact Guarantee/Utility Contract:**
*   *Utility:* The receiver obtains an expression at least as optimal as $E_{opt}$ (since $E_{opt}$ is in the restricted E-graph) using only $O(L)$ verification and extraction time, avoiding the exponential search cost of finding the optimization.
*   *Security (Intended):* Any two traces that generate the same restricted E-graph will yield the exact same $E_{canon}$, destroying steganography hidden in trace ordering or redundant steps.

**Closest Predecessor and Precise Delta:**
*   *Predecessor:* `egg` (POPL 2021) establishes equality saturation and extraction. Certifying algorithms (McConnell et al.) establish the use of verifiable witnesses.
*   *Delta (Unverified):* `egg` focuses on finding *a* low-cost expression efficiently. This construction enforces a *strictly canonical* extraction over a *sender-bounded* E-graph to act as an information-flow sanitizer, attempting to decouple the final AST from the sender's path.

**Full Computation/Observation Cost:**
*   *Receiver Compute:* Parsing the trace, applying $N$ local rewrite checks, building the E-graph, and running a bottom-up deterministic extractor. Total cost is roughly $O(N \log N)$ in trace length, which is strictly cheaper than the sender's unbounded search.
*   *Observations:* The output is exactly the serialized $E_{canon}$. Execution time, memory usage, and fallback status are assumed to be hidden from the public channel (as in the current architecture).

### The Most Damaging Counterexample (Why this fails)

The construction fails to provide a zero-capacity content channel. 

*Counterexample:* Suppose the sender wants to transmit a hidden bit $b \in \{0, 1\}$. There are two distinct, valid optimization paths from $E$ to equally optimal expressions $E_{opt1}$ and $E_{opt2}$, using completely disjoint sets of intermediate lemmas (expressions). 
- If $b=0$, the sender submits Trace 0, generating Restricted E-graph 0. The receiver extracts $E_{canon0}$.
- If $b=1$, the sender submits Trace 1, generating Restricted E-graph 1. The receiver extracts $E_{canon1}$.

Because the restricted E-graphs contain different intermediate nodes, the deterministic extractor operates on different sets. Unless $E_{canon0}$ and $E_{canon1}$ happen to be identical by pure coincidence, the output $E_{canon}$ remains highly dependent on the sender's choice of *which* valid path to take. The sanitizer only removes steganography *within* a specific equivalence class of traces, not across the global space of valid solutions. 

### Verdict: Explicit Rejection

I explicitly **reject** this candidate construction. The proposed bounded check (implementing this on a small set of algebraic rewrites) would immediately demonstrate that maximum pairwise content-distribution total variation (TV) is greater than zero, violating the core noninterference requirement.

**The Unresolved Technical Question:**
The fundamental barrier to general task-preserving rewrite is the **Global Canonicalization of NP-Witnesses**. 

In the 4-node shortest-path toy model, the intermediate state (the true distance vector $D$) is *globally unique* for the task, regardless of the sender's path. Therefore, reconstructing from $D$ strips all sender choices. 

In rich code, compiler optimizations, or any general NP-hard search, the space of valid, optimal witnesses (or intermediate lemmas) is exponentially large and lacks a globally unique, efficiently computable intermediate state. If the receiver restricts its canonicalization to the sender's provided witness (to save compute), it inherently inherits the sender's structural choices (leaking data). If the receiver expands the space to find a global canonical form, it must perform the very NP-hard search it was trying to avoid, destroying the utility (compute reuse) of the rewrite.

Until a mechanism is found that can map an arbitrary valid witness to a *globally unique* canonical witness in polynomial time—which is unlikely for general NP-hard problems without $P=NP$—task-preserving rewrites will remain limited to narrow, polynomial-time solvable domains (like shortest paths) where the "sanitization" offers no asymptotic computational advantage over just solving the problem from scratch.
